Summary

A temporary authentication or network outage sends existing users back to Sign in after restart, interrupting local tracking. An explicit logout during network loss can also leave the browser session active and sign the user back in after reload. Calibrate also lacks the identity mapping and resumable migration tooling needed to prepare existing accounts for Firebase without replacing application IDs or password access.

This PR preserves the last verified, server-scoped identity and cached workspace through transient outages and restarts. Locally saved food and weight additions, corrections and deletions appear in tracking views and remain editable across restart. Reconnection verifies the same account before replaying ordered writes. Confirmed authentication rejection clears the restorable session. Explicit logout persists signed-out intent, bypasses the tracking gate for server revocation, and retries failed revocation without automatically restoring the account. Local cleanup failure cannot skip server revocation. Native late refresh responses are revoked; replacement-account login first completes pending revocation. Active food writes hold only their affected dates; failed writes remain reviewable. Failed food creations, edits and deletions require unchanged-request retry or explicit target-scoped discard before another edit or deletion. Queued deletion cannot hide an entry whose earlier edit failed. Successful cold authentication preserves previously cached tracking even when subsequent data requests fail.

The additive Firebase preparation creates immutable identity mappings and a monotonic credential security version, protects MCP approval against stale credential checks, and adds a sanitized offline inventory command, dry-run-default BCRYPT engine, resumable journal, isolated provider adapter and operator runbook. Existing application IDs, password hashes, owned data and local self-hosting defaults remain intact.

Refs #421. Firebase runtime activation and migration are not complete. This is a draft preparation checkpoint. GCP #422 depends on the remaining runtime foundation.
