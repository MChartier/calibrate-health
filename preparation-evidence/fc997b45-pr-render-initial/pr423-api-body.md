## Summary

Calibrate needs to preserve existing application identities and password access while preparing a Firebase migration. The current database has no immutable provider mapping, MCP approval relies on the local password hash as its concurrency guard, and maintainers have no offline migration inventory or recoverable import journal.

This preparation adds an initially empty, uniquely constrained Firebase identity mapping and a database-enforced credential security version. MCP approval uses that version to reject stale authentication. Existing password writers advance the version automatically, including older local binaries. User IDs, passwords, owned data, legal history and local authentication remain intact; mapping rows do not activate Firebase, and unsupported provider configuration fails explicitly.

The PR also adds a sanitized offline inventory command, a dry-run-default BCRYPT import engine, an append-only filesystem journal, an isolated credential-provider adapter, regression tests and an operator runbook. Collisions are held for resolution; uncertain or partial imports are not blindly retried; successful records are not resubmitted on resume.

Refs #421. **This is preparation, not a completed migration or an enabled Firebase runtime.** Registration/recovery/deletion integration, external-event enforcement and real Firebase rehearsal remain outstanding. GCP #422 follows the completed runtime foundation. Target base: `master` at `4728d4f75b70e6440a9778a42cd2224a300db725`; no unmerged parent. Migration 0045 avoids ordinals already owned by other open work; their branches were not modified.

## Supporting checks and limitations

- Passed locally on Windows/ZBook, Node 24.19.0: 54 focused tests, backend typecheck, dead-code gates, 17 database-helper tests and diff hygiene. Real CI populated upgrade and encrypted rollback/re-upgrade passed. Remaining final-head CI and configured engineering review are being reconciled; independent QA has not run.
- The SQL mapping is preparation metadata. No Firebase account, import, provider activation or live user-data read occurred. Real BCRYPT import/sign-in rehearsal remains unexecuted and requires separately authorized test-project access.
- The journal coordinates one host's importers; it does not freeze SQL/Firebase writers or certify power-loss durability. Live adapters, reviewed recovery and exclusive cross-store write coordination remain required. There is no live apply command.
- Runtime registration/recovery/verification/deletion/session/Wear integration and external credential enforcement remain unfinished. It is not GitHub UI inspection, an application screenshot, or a baseline waiver.
