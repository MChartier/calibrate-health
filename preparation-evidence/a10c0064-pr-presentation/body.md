## Summary

A temporary authentication or network outage currently sends an existing user back to Sign in after restart, interrupting local tracking. Calibrate also lacks the identity mapping and resumable migration tooling needed to prepare existing accounts for Firebase without replacing application IDs or password access.

This PR preserves the last verified, server-scoped local identity and cached tracking workspace across transient outages and restarts. Food and weight operations supported by the existing outbox continue saving locally, with visible pending changes and reconnection controls. Synchronization resumes only after account access is verified; confirmed authentication rejection clears the local session. Offline PWA restart uses the matching exported route shell and cached fonts.

The additive migration foundation creates immutable Firebase identity mappings and a monotonic credential security version, protects MCP approval against stale credential checks, and adds a sanitized offline inventory command, dry-run-default BCRYPT engine, recoverable journal, isolated provider adapter and operator runbook. Existing IDs, hashes, owned data and local self-hosting defaults remain intact.

Refs #421. **Firebase runtime activation and migration are not complete.** This draft is an independently reviewable preparation checkpoint. GCP #422 must wait for the remaining runtime foundation. Base: master at `4728d4f75b70e6440a9778a42cd2224a300db725`; no unmerged parent. Other owners retain their branches; the small FoodTrackingStatus overlap with #419 is recorded in the issue.

## Supporting checks and limitations

- Local final-source browser execution: both maintained offline scenarios plus genuine capture passed (3/3). Service-worker/security tests passed (8), export artifact tests passed (11); preceding focused auth/API/cache tests passed (38) and full API-client suite passed (67). Current-revision CI and configured review are recorded in PR checks and the separate checkpoint comment; independent readiness QA remains pending.
- Local availability covers the cached workspace and existing outbox-supported operations. It does not make server-only operations available offline, grant server access from a snapshot, or guarantee uncached historical data. Browser storage can be cleared by the user/browser. No native emulator or physical-device UI execution is claimed.
- Firebase lifecycle/session/Wear integration, cross-store deletion tombstones, external credential-event enforcement and an authorized real-project import rehearsal remain outstanding. No live users, Firebase provisioning/import, credentials, cutover or deployment were touched. The disk journal coordinates cooperating local writers only; it is not a cross-store freeze or proof of power-loss durability. See the [maintained runbook](https://github.com/MChartier/calibrate-health/blob/a10c00649a338849190b0433e20b85aade7415f8/docs/firebase-migration-preparation.md).

The supplied alternative is a local browser render of the exact API-read-back body with verified embedded images; it is not GitHub UI inspection or a baseline waiver. Independent QA must assess the applicable presentation gate.
- The complete merge diff retains only product code, required schema/ledger changes, maintained regression tests and the operator runbook. Capture/build logs, bundles and historical receipts stay on the dedicated non-merged evidence ref. Draft only; no human-ready, merge, release or cutover approval is claimed.
