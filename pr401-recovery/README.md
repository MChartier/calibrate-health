## Outcome and acceptance

1. **One server entrypoint.** A read-only manual `Release server` request accepts exactly `patch`, `minor`, `major`, `resume`, and `image-only`. Patch/minor/major call the existing cut worker with the selected bump and bound source. Reject unknown/extra/duplicate or mixed recovery inputs before writes. Keep repository/run/attempt/ref/SHA/artifact checks and the current protected-master handler check. Remove the four redundant request/handler files only after equivalent routing is established.
2. **Prepared and image recovery.** `resume` requires the exact prepared commit and version tag, derives the original release branch, and calls the existing post-merge publisher. It must reject an unmerged candidate and must not allocate another version. `image-only` calls only the image worker: no OTA or host deployment; `publish_latest` defaults false and true is valid only for the highest stable release. Conflicting/unattested aliases still fail closed. Preserve `cut-release-handler.yml`, `publish-release-handler.yml`, and `container-handler.yml` as historical certificate caller identities; retain exact signer/source checks, immutable digest reconstruction, and fresh-master allow/revoke precedence.
3. **Current release CI.** Preserve [PR434](https://github.com/MChartier/calibrate-health/pull/434)'s complete exact-candidate gate: lint, tests, builds, production container scan and database upgrade; exact PR/tested-base associations; newest-attempt handling; justified skips only; bounded approval/missing-check waiting; ref recheck after CI inspection; immediate pre-merge check; SHA-locked merge and post-merge parent/tree validation. Missing, zero-job, failed, stale, cancelled and unapproved runs must not authorize merge. Retain blocked validated candidates; retry failed jobs only with unchanged refs, reconcile drift before a fresh cut, and never use the prepared publisher before merge. Keep stage reporting and explicit publication dependencies.
4. **Native wrapper.** `native:release` resolves credential paths, awaits the existing build/sign/verify worker, then submits the verified phone/Wear artifacts and reads them back. A failed build must prevent submit. `--skip-build` verifies/reuses retained artifacts without rebuilding, re-signing or loading signing settings; changed/stale artifacts reject before Play authentication. Keep credential-free prebuild, consuming-stage secret isolation, the internal submit worker, local internal tracks and Console-coordination reminder. Preserve manual build/install/OTA options; do not allocate versions or promote production automatically. Document replacing the public `native:submit` alias with `native:release -- --skip-build`.
5. **Maintained guidance and evidence.** Add a concise canonical deployment chooser and reconcile linked native/recovery instructions with the current CI retention contract. Correct the stale release-time rollback-rehearsal claim. Retain current [maintenance-only audit policy](https://github.com/MChartier/calibrate-health/pull/403); do not restore advisory exceptions, PR package-audit gates or bypasses, and preserve PR container OS checks. Show source-bound non-UI input/output behavior; original doc images remain historical supplementary evidence, not proof of release execution or current behavior.
