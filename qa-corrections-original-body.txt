## Summary

Maintainers currently decide and run server, native and OTA releases separately, which makes unnecessary builds and uncertain retries difficult to avoid. This prepares one manual **Release changed artifacts** entrypoint that compares immutable inputs with each artifact's last verified success, proposes versions and runs only the required existing workers.

The plan preserves Android phone/Wear allocation, exact-candidate CI, signed tags and image receipts. It adds independent iOS build allocation and IPA verification, compatible per-runtime OTA, and durable recovery without blindly repeating uncertain provider requests. Backend/project/profile settings are supplied externally at build time. iOS upload inputs are prepared separately; TestFlight processing and production rollout are not claimed.

Refs #447. **Review order: PR441, then this child.** Actual target: `mchartier/release-entrypoints-recovery` at `cd8932b2`; source parent: `0c26cea`; ultimate target: `master` at `9dc0739`. PR441 is preserved. Managed-hosted PR450 remains a separate integration dependency; its UI is not imported here.

## Test plan and behavior evidence

This is non-UI release tooling. The evidence is [actual synthetic CLI/JSON plans, worker arguments and state transitions](https://github.com/MChartier/calibrate-health/blob/80703680c484c534bcfa0f7ee18760870d2acc6f/behavior.json), with [reproduction and full evidence](https://github.com/MChartier/calibrate-health/blob/80703680c484c534bcfa0f7ee18760870d2acc6f/README.md).

| Starting state and action | Expected and observed |
| --- | --- |
| All verified artifact inputs match; execute the plan | No stages and zero journal/candidate/provider writes. |
| Change only server, either native platform, or either compatible bundle | Select only the corresponding stage; OTA retains the installed native runtime. |
| Change server and both native inputs | Allocate paired Android and independent iOS versions, then run server last through its original candidate/image gates. |
| Lose a provider response, then retry twice | Retain intent, reconcile one operation and reuse its verified result; one provider start total. |
| Retry OTA with an empty provider inventory | Reject another publication. Changed native/configuration/export/channel identities also reject in maintained regressions. |
| Prepare iOS delivery | Build arguments freeze existing credentials; upload arguments select an exact verified store build. Neither command was executed against a provider. |

Maintained fixtures additionally cover stale source, missing/failed CI, incompatible OTA, partial completion, conflicting receipts, concurrency and interrupted cleanup with retained tombstones/readback.
