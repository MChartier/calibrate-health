# Server 0.33.3 / Android 0.2.5 / Wear 0.2.5 release candidate

Status: implementation candidate. Automated release gates are required on one frozen pull-request head. Permanent
signing, physical Galaxy acceptance, external alert delivery, OTA approval, Play Console review, manual accessibility,
legal/support approval, distributed-predecessor validation, and dogfood evidence remain external-launch gates.

## Highlights

- Responsive web/PWA and Android tracking for food, weight, goals, trends, notifications, account management, and
  privacy-safe export/deletion flows.
- Offline Android write replay with account/server isolation, process-death recovery, and deterministic reconciliation.
- Read-only Health Connect activity synchronization that does not replace profile-estimated TDEE or automatically
  change calorie targets.
- Wear OS pairing, cached daily summary, quick actions, undo, offline outbox, Tile, reminders, rotary input, and
  continue-on-phone handoff.
- User-approved bounded calorie-target calibration while preserving configured deficit and estimated TDEE semantics.
- Privacy-safe operational diagnostics, performance budgets, accessibility coverage, visual baselines, and source-bound
  hosted release evidence.

## Database upgrade notes

Tag `v0.14.0` is the actual distributed base and already contains migrations through `0031`. Back up Postgres and
validate the encrypted artifact before any future schema upgrade. Application startup runs `prisma migrate deploy`
before readiness and fails closed when migrations cannot complete.

The hosted release rehearsal starts from the immutable `v0.14.0` schema/data state, upgrades to frozen candidate C,
checks representative records and account portability, then restores the protected pre-upgrade state. This rehearsal
validates repository mechanics; the operator must still validate the real deployment backup destination and restore
authority before launch.

## Compatibility

- Server API: v1; the legacy `/api` alias remains available.
- Minimum phone version: 0.1.0.
- Minimum Wear version: 0.2.0.
- Current phone and Wear version: 0.2.5 (version code 7).
- Phone and Wear must use application ID `app.calibratehealth.mobile` and the same permanent signing certificate for
  Data Layer communication.
- One application process is supported per self-hosted instance; horizontal replicas remain outside this release.

## Rollback

Stop application writes before rollback. Restore the verified pre-upgrade database when reverting across a schema
boundary; changing only the application image is safe only when the older image explicitly supports the applied
schema. After restore, verify readiness, authentication, food and weight writes, account export, native refresh,
offline replay, and phone/watch compatibility before reopening the instance.

Native stores do not support downgrading to a lower version code. Recover a bad native release with a fixed build that
has a higher version code. OTA rollback must remain within the installed native runtime fingerprint.

## Known release-candidate limitations

- Android and Wear UI is English-only; web retains its supported languages.
- Activity is observational and does not automatically adjust the calorie target.
- Native remote push remains disabled unless an operator explicitly configures the approved delivery path.
- Direct FCM, horizontal scaling, smart target-date adjustment, automatic activity-target adjustment, and advanced
  body-composition modeling are not included.
- Hosted emulators use disposable signing only. Permanent signing, physical devices, real alert delivery, production
  configuration, store submission, OTA approval, and long-duration dogfood require operator receipts after C freezes.
