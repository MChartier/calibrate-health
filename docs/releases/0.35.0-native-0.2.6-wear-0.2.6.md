# Server 0.35.0 / Android 0.2.6 / Wear 0.2.6 Play candidate

Status: implementation candidate. Google Play onboarding, permanent signing, tester enrollment, physical Galaxy
validation, and public-channel approval remain owner-operated release steps.

## Purpose

This candidate carries the 0.2.6 phone and Wear runtime contract on the current 0.35.0 source era and adds the
repository-owned Google Play internal, closed, production, and recovery paths. It supersedes the earlier unshipped
0.33.5 implementation record without rewriting that historical source identity.

## Compatibility

- Server API: v1; the legacy /api alias remains available.
- Current phone version: 0.2.6 (version code 9); current Wear version: 0.2.6 (version code 10).
- Minimum phone version: 0.1.0.
- Minimum Wear version: 0.2.0.
- Phone and Wear use application ID app.calibratehealth.mobile and require one Play app-signing certificate for
  installed-package upgrades and Data Layer communication.
- Runtime policy remains Expo appVersion; OTA updates for this native input set target 0.2.6 clients only.

## Distribution requirement

Build both AABs from one exact 0.35.0 source commit and upload them atomically to the phone and Wear internal tracks.
Only after Google Play exposes the exact source markers and bundle digests may the protected `native-v0.2.6` tag
identify that source. Promote those same version codes without rebuilding.

## Recovery

Rerun failed jobs in the original workflow run while its exact candidate artifact remains available. If Google Play
accepted the bundles but the workflow could not complete or tag the response, use the `recover-internal` operation;
it reconstructs the source-to-bundle-digest receipt from Play and creates no new build or Play edit commit.

## Rollback

Native stores do not support downgrading. Recover a bad native release by preparing 0.2.7 or later, which allocates an
odd phone version code greater than 9 and an even Wear version code greater than 10. Never reuse
`native-v0.2.6` for another commit. OTA rollback must remain within the installed 0.2.6 runtime fingerprint.
