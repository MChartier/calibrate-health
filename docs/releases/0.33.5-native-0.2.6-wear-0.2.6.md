# Server 0.33.5 / Android 0.2.6 / Wear 0.2.6 release candidate

Status: implementation candidate. Permanent signing, physical Galaxy validation, OTA promotion, Play Console review,
and dogfood checks are owner-discretion steps for an actual native distribution, not repository release gates.

## Purpose

This native patch release advances the phone and Wear runtime contract after the 0.33.5 application stack changed
native inputs without advancing the installed application version. Expo OTA publishing correctly rejected that mismatch
because an update built for the changed runtime must not target existing 0.2.5 binaries.

## Compatibility

- Server API: v1; the legacy /api alias remains available.
- Current phone version: 0.2.6 (version code 9); current Wear version: 0.2.6 (version code 10).
- Minimum phone version: 0.1.0.
- Minimum Wear version: 0.2.0.
- Phone and Wear use application ID app.calibratehealth.mobile and require the same permanent signing certificate for
  Data Layer communication.
- Runtime policy remains Expo appVersion; OTA updates for this native input set target 0.2.6 clients only.

## Distribution requirement

Build and distribute newly signed 0.2.6 phone and Wear artifacts before approving an OTA update for this runtime.
The retained 0.2.5 release notes remain the historical candidate record. The reserved native-v0.2.6 tag must point to
the exact source commit used for both signed artifacts.

## Rollback

Native stores do not support downgrading to a lower version code. Recover a bad native release by preparing a new
patch semantic version (0.2.7 or later), which allocates an odd phone version code greater than 9 and an even Wear
version code greater than 10. Never reuse `native-v0.2.6` for another commit. OTA rollback must remain within the
installed 0.2.6 runtime fingerprint.
